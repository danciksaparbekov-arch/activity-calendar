# Что делаем вместе

Календарь совместных планов для друзей. Один день — большая карточка с коллажем из скриншотов;
при наведении видны заголовки событий, внутри дня — лента по времени, кнопка «Я иду» и список свободных друзей.

**Стек:** Vite + React (HashRouter) · Supabase (Postgres, Auth magic-link, Storage) · GitHub Pages.

## Возможности

- Календарь месяца, карточки дней с коллажем (до 4 картинок), заголовки по наведению.
- Страница дня: события по времени, описание, галерея, «Я иду» / «Отказаться», кто идёт.
- «Я свободен»: каждый добавляет промежутки времени; в календаре видно, сколько друзей свободно.
- Админ (только вы): создаёт, правит и удаляет события, загружает картинки.
- Два способа входа: по паролю и по ссылке из письма. Регистрация только по коду приглашения (проверяется в БД). Читать данные могут только вошедшие.
- Комментарии к событиям (пишет любой вошедший), гости по имени в списке «кто идёт».
- Круги общения: у каждого круга свой код, друзья видят только свои круги, админ — все (переключатель в шапке).

## Запуск с нуля

1. **Supabase.** Создать проект на [supabase.com](https://supabase.com). В *SQL Editor* выполнить [supabase/schema.sql](supabase/schema.sql).
2. **Ключи.** *Project Settings → API*: скопировать Project URL и anon key в `.env` (шаблон — `.env.example`).
3. **Вход: по паролю и по ссылке из письма.** Ссылкам нужен свой SMTP (*Authentication → SMTP*, например Gmail с паролем приложения),
   иначе встроенная почта Supabase даёт 2–3 письма в час. *Confirm email* (*Providers → Email*) держим **выключенным**: регистрация идёт по паролю без письма
   (ссылка из письма на телефонах часто открывается в другом браузере и вход не срабатывает), доступ защищает код приглашения.
   Ссылка из почты остаётся только как способ входа. Если пользователь «застрял» неподтверждённым:
   `update auth.users set email_confirmed_at = now() where email = '...';`
   Задать код приглашения: `insert into public.app_settings (key, value) values ('invite_code', 'ВАШ-КОД');`
   Ссылка из письма ведёт на адрес сайта — он должен быть в *Authentication → URL Configuration → Redirect URLs*.
4. **Локально:** `npm install` → `npm run dev`. Зарегистрироваться (имя, код, email, пароль).
5. **Стать админом.** После регистрации выполнить в SQL Editor (с вашим email):
   ```sql
   update public.profiles set is_admin = true
     where id = (select id from auth.users where email = 'you@example.com');
   ```
6. **Забыл пароль** — админ задаёт новый в SQL Editor (команда в конце `migrations/003_password_auth.sql`).

### Обновление существующей базы

`schema.sql` — полная схема для нового проекта. Если база уже создана, выполняйте только недостающие
файлы из [supabase/migrations/](supabase/migrations/) по номерам в SQL Editor:

- `002_comments_guests.sql` — комментарии к событиям; гости по имени и отметки «кто идёт» от админа.
- `003_password_auth.sql` — вход по паролю и регистрация по коду приглашения (перед запуском подставить свой код).
- `004_circles.sql` — круги общения: события, люди и коды приглашения по кругам, изоляция через RLS.
  Текущие данные переезжают в круг «Основной» с прежним кодом. После неё код приглашения живёт в `circles`
  (раздел «Круги» на сайте), а `app_settings` больше не используется.

Для нового проекта: `schema.sql`, затем `004_circles.sql` (она перекроет проверку кода из `schema.sql`).

**Порядок выкладки:** сначала миграция в Supabase, потом `git push` (иначе сайт будет обращаться к таблицам, которых нет).

## Деплой на GitHub Pages

1. Создать репозиторий, запушить проект в ветку `main`.
2. *Settings → Secrets and variables → Actions*: добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. *Settings → Pages → Source*: **GitHub Actions**.
4. Каждый пуш в `main` собирает и публикует сайт ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)).

## Безопасность

- anon key в браузере — это норма: защиту дают политики RLS в `schema.sql`. `service_role` ключ в проект не класть.
- Менять события и грузить картинки может только `is_admin`; друзья управляют лишь своими подписками и доступностью.
- Колонка `is_admin` недоступна для обновления клиентом (права выданы только на `name`).
- Бакет картинок публичный, но имена файлов — случайные UUID. Если нужны строго приватные — перейти на signed URL.
- Регистрацию защищает код приглашения: триггер на `auth.users` отклоняет создание пользователя с неверным кодом
  (и по паролю, и по ссылке). Код лежит в `app_settings`, клиентам эта таблица недоступна.
  Вход ссылкой не создаёт новых аккаунтов (`shouldCreateUser: false`).
  Сменить код — `update public.app_settings set value = '...' where key = 'invite_code';`
